PRODUCT NOTE

把 AI 放进研究工作流

价值假设、能力边界与可验证的交付。

用户与核心任务

目标用户：覆盖 5–15 家公司的初级基本面研究员。在年报披露后，将本期与上期财报对比，形成需要向资深研究员汇报的变化清单。

现有流程：定位文档 → 摘录指标 → 对齐口径 → 手工计算 → 阅读经营讨论 → 写底稿 → 主管复核。见微聚焦其中的指标核查与证据组织，不做选股、估值或交易执行。

为什么需要 AI

规则适合数值提取与核算；搜索适合定位原始文件。LLM 的增量价值在于跨期经营表述对齐、识别语义变化和提出待验证的解释。模型不负责计算，也不能为推断补造依据。

人机分工

用户确认口径 → 工具提取与标准化单位 → 工具计算 → 模型输出带逐字证据的线索 → 服务端核验证据是否属于原文 → 用户确认 / 否决 → 导出底稿。缺失字段、负基数、模型失败均显式展示。

验证计划（目标值，尚非实验结果）

指标定义与目标
任务效率5 名研究用户交叉完成 10 组财报核查，比较人工与辅助流程中位用时，目标降低 30%。
事实准确率人工标注字段、单位、口径；可计算指标准确率目标 ≥ 98%。
证据覆盖率每条线索须有可定位的跨期引文，目标 100%；引文存在不等于因果正确。
研究线索质量双人盲评可用率目标 ≥ 80%，记录分歧；与纯规则、通用聊天分别比较。
安全失败缺字段、冲突、模型异常等不得显示“全部正常”；目标 100% 显式暴露。

当前实现边界

无 API 密钥时运行规则演示，仅支持 4 个标签明确的指标；不宣称具备语义抽取能力。预留服务端 LLM 接口，配置后才启用跨期语义分析。扶摇 / iFinD 尚未接通，不展示伪造实时数据。

TXT / 粘贴原文；不支持 PDF 解析、自动下载、跨公司口径校准、鉴别文档真实性。报告年份、来源与统计口径依赖用户确认。保存在本机的数据可删除；不要输入未授权的非公开信息。

金融数据连接优先评估扶摇和 iFinD；当前不依赖行情数据，因为核心任务是对原始财报取证。AI 仅给待核查线索，不给确定性收益预测与直接买卖建议。
