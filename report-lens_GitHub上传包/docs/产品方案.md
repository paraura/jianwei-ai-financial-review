# 见微：财报变化核查助手

## 一句话定位
帮助初级研究员在年报更新后，把两期财务变化及经营讨论整理为“有出处、能复核”的底稿，让资深研究员将时间用在解释与判断上。

## 问题与证据层级
财报对比需要跨文档定位、指标对齐、计算和证据整理，具有重复性且容易遗漏单位与口径。本项目将其作为产品机会假设；尚未进行真实访谈，不能断言行业普遍耗时或付费意愿。下一步访谈5名研究员，收集脱敏底稿和任务用时，确定使用频率与最重要的遗漏类型。

目标用户：覆盖5–15家公司的初级基本面研究员；触发点：新年度年报披露、准备周会变化汇报。任务终点：形成资深研究员能追问和复核的变化清单，不是形成交易决策。

非目标：个性化资产配置、股票推荐、涨跌预测、自动交易、完整财务模型、PDF解析、识别造假。优先把一个窄流程做透，避免同时做行情、研报和持仓问答。

## 用户流程与决策权
1. 用户输入同公司两期年度财报摘录，记录出处；人工确认同合并与累计口径。
2. 工具抽取四项明确标签指标；检查缺失与重复，按元标准化计算。
3. 用户查看变化及原值。零负基数和缺字段显式阻断对应计算，不生成“正常”结论。
4. 如已配置模型：服务端把原文与计算结果送给模型，模型提出跨期语义变化及待验证问题；引文先经程序匹配，再由人审核。
5. 用户回到原文核查，逐项确认/否决，填写调整原因。
6. 导出包括来源、原文、公式、状态、推断和人工反馈的底稿；可保存本机摘要。

## AI 相对替代方案的增量
Excel/规则：计算可靠、成本低，但难理解经营表述变化；本产品保留这层工具，不让模型重算。
搜索/数据终端：善于找到文档和字段，但用户仍需跨期对齐并组织证据；本产品将证据紧邻变化呈现。
通用聊天：可总结，但可能编造引文、混淆时期；本产品用结构化输出、跨期引文匹配、异常状态与人工复核限制风险。
人工：对口径与因果判断不可替代；AI 只减少初稿与证据组织工作量。

真正 AI Native 的价值应出现在非固定模板的语义对齐上。当前规则演示能验证交互和核算，不能证明这一增量；需接入真实模型并做对照评测。

## 系统与状态
浏览器输入 → 规则提取与计算 → 可选 /api/analyze → 服务端模型调用 → JSON/逐字引文/建议词检查 → 推断卡片 → 人工反馈 → Markdown导出。

状态：待输入、口径未确认、执行中、指标完整、指标部分失败、模型未配置、模型失败、模型成功、待复核、已确认、有问题。部分失败与模型成功相互独立，模型不能掩盖字段缺失。

模型不是自主交易 Agent；当前是工具约束的分析工作流。未来只有在来源获取与任务状态可控后，才增加文档检索与多步重试。

## 成功标准与验证设计（计划）
招募5名研究用户，以10组脱敏/公开年度财报进行交叉任务，随机分配人工流程、规则辅助、LLM辅助顺序，避免重复学习偏差。双人标注指标、证据与线索质量，保留分歧并仲裁。

- 任务中位用时降低30%：从开始定位到完成可交付底稿，包含人工纠错；记录模型延迟与成本。
- 数值准确率≥98%：分母为人工标注的可计算字段，检查数值、单位、年份与口径，不能仅看公式结果。
- 引文可定位率100%：每条线索至少有双期原文证据；证据相关性另行评估。
- 线索可用率≥80%：双盲评是否值得进一步核查，不能以用户点击确认直接替代质量。
- 安全失败暴露率100%：字段缺失、冲突、接口失败、无证据等都给明确状态。

上述均为验收目标，尚无真实实验数据。自动化14项测试仅证明有限代码行为，不代表上述产品指标达标。

## 迭代优先级
P0：接入真实模型、真实原文样本、人工金标与供应商超时测试；保证评审可访问。
P1：评估扶摇财务数据与原文交叉校验、PDF页码定位、重述口径提示、模型线索逐条复核。
P2：机构权限、审计记录、协作复核、配额与质量监控。只有验证核心任务频率和节省时间后，再评估团队席位收费。
