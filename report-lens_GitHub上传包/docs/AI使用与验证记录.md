# AI 使用与验证记录

日期：2026-10-26。以下是本次实际过程，不是虚构候选人经历。

## 使用工具和职责
Codex：读取题目、梳理交付标准、选择产品方向、编写网页与服务端适配、自动测试、说明材料。Sites：网站注册、源码同步和部署。Node.js：核算与服务端测试。本地浏览器：检查示例主流程、证据和人工复核状态。

候选人实际给出的信息：应聘 AI 产品经理；暂无 API，优先可演示版本。候选人尚未亲自完成用户测试、真实模型质量验证或金融数据接口验证。不得将 AI 的操作改写成候选人亲自完成的研究。

## AI 帮助形成的产品决策
将开放式“投资助手”缩小到财报变化核查；以原文证据与人工复核为结果，而非涨跌判断。保留规则计算，把模型用于语义变化解释。无密钥时明确显示规则演示。

## 本次开发中修正的问题
1. 最初方向容易把可交互演示等同于AI产品完成：增加完成度声明，区分规则模式、真实LLM调用与模拟测试。
2. 移动布局原先会隐藏侧边导航：改为窄屏横向导航，保留产品说明和本地记录入口。
3. 新任务可能沿用旧任务反馈与“已保存”按钮状态：重新运行时清空反馈、重置保存状态。
4. 限制模型引文：输出必须是双期连续原文片段，缺失或伪造引文拒绝展示；仍需人工评估相关性。
5. 对零和负基数禁用常规同比；不让模型或计算器给出误导性百分比。

这些是 AI 实施的修正，候选人可以复核后写入自己的理解，不能声称由本人先发现。

## 未完成的验证
没有调用真实LLM；没有扶摇/iFinD成功调用；没有真实公司原文抽取评测；没有真实研究员访谈或A/B测试；没有收益或效率提升的实际测量。所有产品指标是目标值。

## 建议候选人接手
自己走一遍示例和异常输入；用真实公开财报摘录复核至少一组指标；接入服务端模型后，记录供应商、模型、时间、输入输出、失败案例、修改前后结果；再填写真实的本人观察。不要把尚未完成的步骤写成已完成。
