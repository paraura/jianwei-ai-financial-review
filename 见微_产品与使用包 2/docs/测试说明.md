## 自动测试

需要Node.js 22+，在仓库根目录运行：

```sh
npm test
npm run build
node scripts/validate-artifact.mjs
```

自动测试覆盖14项：四指标与行号、跨单位换算、缺失字段、重复冲突、零负基数、缺单位、倒置期间与未确认口径、未配置模型、密钥不从配置接口泄露、模拟模型接口失败、模拟伪造引文、模拟违规建议、模拟有效结构、原文脚本作为文本输入。

2026-10-26本地运行14项通过，构建及Worker ESM验证通过。代码测试不代表模型或财务判断质量。模型相关测试为模拟响应，没有调用真实供应商；原文脚本测试仅覆盖指标提取，不是完整安全审计。

## 手工验收

按sample-data内5组案例依次导入，比对指标数、同比、差额与失败提示。随后验证：

1. 查看证据，检查两期原文、来源、行号和公式。
2. 确认一项、否决一项，观察确认计数；写明人工意见。
3. 导出底稿，用文本编辑器打开，核对来源、人工状态与问题提示。
4. 保存本机摘要，进入记录页查看并清除。
5. 修改原文后重新运行，确认旧复核状态和意见清空。

浏览器已实际检查：示例4项核算、原文证据展开、人工确认计数变化；公开站无登录请求返回HTTP200。其余手工步骤是复测清单，不作为已经完成的操作记录。

## 真实模型验证

配置模型后记录供应商、模型版本、时间、输入与输出、延迟、成本和人工判断。分别测试语义变化、无充分证据、无效凭据、超时、伪造引文、文本中的注入指令与违规建议。服务端关键词检查和逐字匹配不能保证防住所有风险，必须人工复核。

## 产品价值验证

先进行研究员访谈，再采用人工、规则辅助、LLM辅助三组交叉任务。以可交付底稿用时、字段准确率、线索可用率和异常暴露率评价；数值目标与实验设计见README。尚未进行真实用户实验，不报告效率提升百分比为实测成果。
