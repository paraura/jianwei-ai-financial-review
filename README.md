# 见微｜财报变化核查助手

**面向初级基本面研究员，把两期财报中的数字与经营表述变化，整理成带原文证据、可人工复核的研究底稿。**

[打开在线工作台](https://report-lens-audit-1026.citrusiris5.chatgpt.site/) · [使用指南](docs/使用指南.md) · [测试数据与预期结果](sample-data/README.md) · [测试说明](docs/测试说明.md)

> 体验入口：打开网站 →「载入示例」→「开始核查」→ 查看证据 → 人工复核 → 导出底稿。无需注册或 API 密钥。示例为构造数据，当前在线版本运行规则核查；LLM 语义分析需另行配置服务端模型。

## 产品解决什么问题

每当新年度财报发布，研究员需要回答两个问题：**公司相比上期发生了什么变化？哪些变化需要继续研究？**

现有流程通常分散在财报阅读器、表格和笔记里：查找指标、对齐单位与口径、计算变化、对比经营讨论、记录出处，再向资深研究员汇报。数值计算本身并不困难，反复定位和组织证据才是产品希望减少的工作。单位、时期或报表范围混淆，也会让正确的公式产生误导结果。

见微将这些动作收敛到一个核查工作台：**变化旁边有原值，原值旁边有证据，研究判断保留人工复核。**

这是待验证的用户需求假设，尚未通过正式研究员访谈测定频率、耗时或付费意愿；不以未经测量的“行业平均耗时”作为论据。

## 为谁设计，在什么时候使用

- **目标用户**：需要持续跟踪多家公司的初级基本面研究员。
- **使用时机**：年度财报更新后，为周会或专题研究准备初步变化清单。
- **输入**：同一公司、同报表范围、可比口径的两期年度财报文本摘录及出处。
- **输出**：包含数值变化、原文位置、异常状态与人工意见的 Markdown 研究底稿。
- **任务边界**：辅助发现与核查变化，不进行股票推荐、收益承诺、涨跌预测或自动交易。

## 为什么需要 LLM，而不是只用 Excel 或搜索

**数值计算交给规则工具，语义变化理解交给 LLM。**

| 任务 | 合适的方法 | 设计原因 |
| --- | --- | --- |
| 找到原始公告与财报 | 搜索 / 数据终端 / 用户提供 | 解决来源获取，保留原始证据 |
| 提取明确标签、检查缺失、统一单位、计算同比 | 规则与计算工具 | 可复算、低成本，不依赖模型猜测 |
| 对齐两期不同措辞，发现渠道、信用政策等经营变化 | LLM | 需要跨文本的语义理解，固定关键词难以覆盖 |
| 判断口径可比、证据相关和原因是否成立 | 研究员 | 文本匹配不能替代专业判断 |

例如，基期说“主要通过经销渠道销售”，本期说“扩大直销业务，对部分客户延长信用期”；同时工具计算出应收账款增长。LLM 的角色是提出**“信用政策变化是否与应收账款变化有关，仍需核查”**，并附上两期原文，而不是直接认定原因。

相对通用聊天，见微的设计重点是工具约束、出处绑定、显式失败和人工复核。引文存在只证明可追溯，不证明解释正确。

当前采用固定编排的分析工作流，不需要能自主执行交易的 Agent。只有当来源检索、任务状态与权限可控时，才考虑增加自主检索和重试。

## AI 如何使用数据和工具

```text
两期原文与出处
  ↓ 用户确认主体、期间、报表范围与口径
字段提取工具 → 缺失 / 重复检查 → 单位换算与同比计算
  ↓
LLM 跨期语义对齐〔配置模型后〕
  ↓ 输出：待验证假设 + 双期逐字引文 + 下一步问题
结构校验 → 引文原文匹配 → 高风险建议词检查
  ↓
研究员查看证据、确认 / 否决、补充说明
  ↓
导出研究底稿
```

数据来自用户粘贴或导入的 TXT 摘录；在线示例为匿名构造数据。目前未连接扶摇或 iFinD，不展示实时行情或伪造接口结果。后续可评估用扶摇财务字段交叉核对数值，用 iFinD 补充事件线索，核心证据仍应回到原始公告。

模型仅接收用户原文及已计算结果，不能改写计算器输出。服务端只接受结构化线索，并核对引文是否出现在对应原文中。未配置、调用失败、证据校验失败均明确提示，不静默生成正常结论。

## 用户实际如何完成任务

1. **建立任务**：填写公司、两期年度，粘贴原文或导入 TXT，记录来源。
2. **确认可比性**：用户核实同主体、合并范围、累计口径及重述情况，再勾选确认。
3. **查看变化**：核算营业收入、归母净利润、经营活动现金流净额、应收账款。
4. **回到证据**：点击“查看”，核对原文、摘录行号、单位和计算公式。
5. **形成判断**：逐项确认或标记有问题，补充复核意见；模型线索仍需人判断。
6. **带走结果**：导出 Markdown 底稿，或在本机保存任务摘要。

完整的按钮说明、输入格式与异常处理见[使用指南](docs/使用指南.md)。

## 如何验证价值

价值验证分为三层：**事实可复核、用户能完成任务、AI 相对替代方案有增量。**

| 层面 | 验证方法 | 指标与计划目标 |
| --- | --- | --- |
| 证据可靠 | 人工核对数值、单位、时期、出处；双人评估线索与原文是否相关 | 字段准确率 ≥98%；线索引文可定位率 100% |
| 工作流可用 | 观察用户从输入到导出，记录卡点、误解和纠错 | 任务完成率、返工次数、可交付底稿耗时 |
| 时间价值 | 对比人工、规则辅助、LLM 辅助三种方式，计入人工纠错时间 | 中位任务耗时降低 30% |
| AI 质量 | 双盲评估线索是否值得进一步核查 | 线索可用率 ≥80%；另记无依据解释率 |
| 安全失败 | 注入缺失、冲突、非正基数、模型失败等情况 | 异常显式暴露率 100% |

**以上是验证目标，不是实测成果。** 计划先访谈 5 名研究用户，再用 10 组公开或脱敏财报做交叉对照，平衡任务顺序，控制重复学习影响；同步记录模型版本、成本和延迟。比较规则辅助与 LLM 辅助，才能识别真正来自模型的增量。

当前证据：14 项自动测试通过；浏览器实测了示例核算、原文证据展示和人工复核计数。尚无真实研究员实验或真实模型质量评测。[查看测试说明](docs/测试说明.md)

## 当前能力与边界

| 当前可使用 | 当前不支持 / 尚未验证 |
| --- | --- |
| 双期年度文本输入、TXT 导入、4 项明确标签指标核算 | PDF / OCR、自动下载财报、通用表格识别 |
| 原值、单位、出处、摘录行号与公式展示 | 自动验证来源真实性与披露时点 |
| 缺失与重复提示、非正基数禁用常规同比 | 自动识别合并口径变化或财务重述 |
| 人工复核、意见记录、底稿导出、本机摘要 | 多人协作、机构审计与生产级权限 |
| 服务端 LLM 适配、结构及引文校验代码 | 在线真实 LLM 推理与供应商兼容性验证 |

20% 是演示中的显著变化阈值，不是实证建立的风险评级。无论是否接入模型，都不应把变化标记当作买卖信号。
